# Parity with the prototype

ADR-0069 §3: this app replaces the prototype on Dev once every row below is
**done**. The reference is the old prototype, kept unbuilt as an archive in
[`studio-frontend-poc/`](../../studio-frontend-poc/) in its latest version
(everything main changed in it up to the merge that moved it there); the
state this app was copied against is `00828880`
(`git show 00828880:studio-frontend-prototype/src/…`). A file the rows below
name as "the prototype's" is under `studio-frontend-poc/src/`. The
`studio-frontend-prototype` image, and so the POC host on Dev, is this app
from that merge on.

**Who takes it**:
- **shell** is the host app (`src-app/app`).
- A kit name is a built-in kit (ADR-0068 §7). Built-in kits become **base
  kits**, installed by the platform for every organization (ADR-0069 §4).

**Here today** says what this app already has (from the `studio-frontend`
copy).

**State** is one of:
- `todo`
- `partial`: the screen exists here, without everything the prototype's has
- `done`

It distinguishes delivered behavior from the target architecture; marking the PR
ready does not mark the ADR-0070 migration complete. The `todo` and `partial` rows
above remain the detailed parity inventory.

  infrastructure, kind and description operations (#1012); documentation-quality
  proposals shared by the Issues screen and MCP (#1013); model builds and status,
  selected sources, coverage, commit/branch provenance, stated/interpreted facts,

### Next: the layered domain model

The authoritative decisions and dependencies are in
[ADR-0070](../../docs/adr/0070-studio-keeps-a-core-model-and-each-kit-brings-the-types-its-screens-show.md)
and its [type/relationship analysis](../../docs/design/domain-model-split.md).

1. **#1030 completed:** seed ownership annotations, generation from the actual
   Studio seed, and regression checks for core inheritance and all documented
   incoming kit dependencies. The boundary check includes the legacy
   `kit.introduces_type_22` ambiguity documented in the analysis. Core has `file`.
2. **#1031 completed:** gear requirements are stored separately in
   `gear_declarations`, with an explicit declaring gear for held and open types.
   Repeated/partial declarations are additive and idempotent; holder collisions
   are refused; import/revert cannot replace trusted needs. The compatibility
   projection still feeds the flat reader until #1032; this does not implement
   the dormant visibility rules of #1033.
3. #1032: compose shared core, gear requirements, installed kit declarations and
   organization overrides; migrate existing stored flat models without rewriting
   object identities or losing custom fields/history. Property slice delivered: pinned kit property/lifecycle sources and named
   organization overrides/tombstones survive upgrade, source gaps, reinstall,
   restart and history replay/revert. Same-version legacy sources are adopted;
   unknown historical versions are refused with a recovery instruction.
   Core slice delivered: Studio's own types compose as a pinned running-core
   layer under type- and field-level organization overrides, migrated once per
   stored model with an equality check, a complete-read guard and an
   irreversible boundary. Still pending: kit types' entity-level overrides, one
   composition for gear/kit/core layers, head invalidation on install/deploy and
   showing a refused migration to administrators.
4. #1033: installed / dormant / absent states. Delivered: dormant types and
   fields are left out of `GET /types` unless an administrator asks
   `include=dormant` (Admin › Studio domain model does); people's writes are
   refused with `DOMAIN_TYPE_DORMANT` naming the kit while the holding gear's
   sync keeps writing; a member's query answers `DOMAIN_TYPE_NOT_INSTALLED`;
   reinstalling makes the same objects writable. Still open: the
   administrator's "remove what the kit left" action.
5. #1034–#1038: move feature definitions and their incoming relations/tabs into
   their owners, then lifecycle, Git and Assistant; retire `gears` and numbered
   package relations. Keep existing graph type ids and registry schemas stable.
6. #1039: complete Inbox and status ownership, including the permission-aware
   behavior of MCP tools for uninstalled kits (`KIT_NOT_INSTALLED`).
